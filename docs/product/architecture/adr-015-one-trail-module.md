# ADR-015: One Trail Module — The KPI Report Is a Pure Derivation and the Entry Port Sheds the Trail

## Status

Accepted (2026-11-23, architecture review via `/improve-codebase-architecture`; no feature). Supersedes in part ADR-009 and ADR-011 where they describe the trail's write path as `EntryStorePort.append_event` and its read path as name-parameterised queries in `shell/telemetry_store.py`. Relies on ADR-005 (pure core, adapters injected at the composition root), ADR-009 (routes decide WHEN to emit), ADR-011 (the `backdated` payload word), ADR-014 (the precedent: one pure derivation, one seam, replace don't layer).

## Context

The trail had no single home. Its vocabulary (six event names, the beacon's closed surface/control/value sets, `parse_study_signal`) sat at the top of `web/routes.py`. Five emission sites each ran the same `store.append_event(ts=clock.now_utc().isoformat(), name=..., payload=json.dumps(...))` by hand. The all-time counter lived on `EntryStorePort.count_events` (one adapter, two callers), while the three windowed readers (`count_events_since`, `entry_ms_samples_since`, `backdated_saves_since`) were free functions in `shell/telemetry_store.py`, partially applied on `db_path` at the composition root and passed to `build_router` as three callables. `GET /stats` then hand-assembled seven counters plus `speed_summary`, `_p90` and `_kpi_week_start` — all of which were pure, and all of which lived in the shell. Those three callables were most of `build_router`'s remaining kwargs after ADR-014.

Two consequences followed. The KPI derivations — the only non-trivial logic the trail has — could not be property-tested except through HTTP over a seeded SQLite file. And the `/stats` contract (which keys, which week, which payload words) was pinned by nothing but the handler's body.

## Decision

**One module, the Trail, in two halves: a pure core that owns the vocabulary and the report, and a thin shell that stamps once and reads once. Its single driven adapter is the SQLite `events` table, behind a port of its own.**

- `core/trail.py` (pure, clock-free, imports nothing from the shell): `EventName`, the closed enum of on-trail names (`.value` is the on-trail spelling; the retired `trend.view.opened` stays so the frozen-historical counters keep reading); `Event(ts, name, payload)`, one parsed row — `name` deliberately a plain string, because the append-only trail may hold names the code no longer speaks; `parse_study_signal` and the study vocabulary, moved verbatim from routes; `kpi_week_start`, `speed_summary` and `_p90`, moved verbatim; and **`kpi_report(events, today) -> dict`**, the whole `/stats` body: two all-time counters, five rolling-week counters, the KPI-8 payload predicate and the KPI-1 speed summary, derived from the sequence of events and the day it is read on. Order of events never matters.
- `shell/trail.py`: `Trail(store, clock)` with exactly two methods. `mark(name: EventName, payload=None)` stamps `clock.now_utc().isoformat()` **once, here**, and writes the payload as `json.dumps(dict(payload))` — the same bytes the five hand-written sites produced, so new rows and historical rows are indistinguishable. `report()` reads every event and returns `kpi_report(events, today=clock.now_utc().date())`. Marked `# probe-exempt`: it is the module over the port, not a driven adapter.
- `ports.py`: `EntryStorePort` loses `append_event` and `count_events` and is the record's port only. A new **`TrailPort`** carries `append_event(ts, name, payload)` (a row, string-shaped: it is the storage grammar the integration test seeds by hand) and `all_events() -> list[Event]` (parsed, append order). `SqliteEntryStore` satisfies both protocols structurally; `all_events` parses `ts` with `datetime.fromisoformat` and `payload` with `json.loads`. `count_events` is removed rather than folded: with the report pure, the adapter's only read is "everything", and a `since` parameter with one caller passing `date.min` is a parameter nobody varies.
- Routes keep deciding **when** (ADR-009) and call one thing: `trail.mark(EventName.X, payload)`. The beacon's swallow-and-log of a failed append stays in the route, because only the beacon is fire-and-forget. `GET /stats` is `return trail.report()`. `build_router(..., trail=trail, ...)`: the three telemetry callables are gone, 8 → 6 kwargs.
- `shell/telemetry_store.py` is deleted; `speed_summary`, `_p90`, `_kpi_week_start` and the vocabulary block leave `routes.py`. Nothing is layered over the old functions.

The report's rolling week keeps the shipped rule exactly: an event counts when stamped on the week's first day (today − 6, the 1W scale's own window) **or any later day**, with no upper edge. The clock stamps every row, so a "future" row cannot occur in production, and the report does not second-guess the trail; the property oracle says so in as many words rather than inventing a bound the code never had.

## Alternatives Considered

- **Keep the windowed readers, give them a module and a port (`events_since(name, since)`)**: Rejected. It tidies the file layout but leaves the derivations in the shell; the report still hand-assembles eight queries per read, and `speed_summary` stays untestable except through HTTP. The pure derivation is the point.
- **A `KpiReport` frozen dataclass instead of a dict**: Rejected for now. The dict *is* the HTTP contract, and the property suite pins its exact key set; a dataclass plus a wire translation would be a second place for the same seven names. Revisit if a non-HTTP consumer appears.
- **Event timestamps kept as ISO strings in `Event`, compared lexicographically as before**: Rejected. The adapter knows the storage format; the core should see a `datetime` and frame the week on `.date()`. Behaviour is identical for every row the clock has ever written.
- **`Trail.mark` returning the stamp it used, so `POST /entries` can reuse it for `entries.logged_at`**: Rejected. It couples the entry's own `logged_at` to the trail's write order (the upsert must precede the event so a crash between them leaves a row without an event, never an event without a row). The save reads the clock for its own `logged_at` and the trail reads it for the event; with the fake clock they are equal, with the real one they differ by microseconds, and nothing reads them as a pair.
- **An `EventName` enum vs. string constants**: enum chosen. `mark(name: EventName)` makes "free text on the trail" a type error at the one write entry point, which is the structural guarantee ADR-009 argued for at the beacon, now extended to every emission.

## Consequences

- Positive: the KPI derivations have a property surface (`test_trail_report_properties`: the exact `/stats` key set, all-time vs. rolling-week framing, study = opens + taps, repairs = backdated saves, speed = timed saves with honest nulls, order invariance, the inclusive p90) and the vocabulary gate is tested in the core; the clock is read for a stamp in one place; the trail's port is read-only at the core and write-once at the shell; `build_router` carries no telemetry beyond the trail. `test_repair_count_query` (hand-seeded SQLite) keeps passing through the new interface, so the seeded-row regression net is intact.
- Negative / disclosed: `/stats` now reads the **whole trail** into memory on every call (one `SELECT`, no `WHERE`) instead of eight filtered `COUNT`/`SELECT` queries. At one user and a handful of events per day that is a few thousand rows a year; it is noted here so that the day it matters, the fix is a `since` on `all_events` chosen by the report, not a return of the derivation to SQL. `EntryStorePort` changed shape — the first port change since DELIVER — and ADR-009's "no port change" clause is superseded; the acceptance composition was untouched because it only ever spoke HTTP.
- Mutation (per-feature strategy, cosmic-ray 8.4.3, git-filter against the base branch): 122 executed on `core/trail.py` + `shell/trail.py`, 96 killed, 26 surviving, all equivalent (22 annotation `|` mutants, one `|`→`^` on disjoint frozensets, one keyword-only marker, two inside the single-sample branch `speed_summary` guards): **96/96 = 100 % effective**. The three real first-pass survivors — `frozen=True` on `Event`, `==`→`<=` on the save-name filter, and an `is True` that was stricter than the shipped truthiness rule — were closed by tests or by restoring the shipped predicate.
