## Feature Summary and Business Context

**US-015 — stalled progress looks stalled.** The smoothed trend removes daily noise, but the chart's auto-zoomed y-axis put it straight back: with the record plateaued between 77.1 and 77.3 kg for a month, 200 g of residual wobble filled the full 320 px and the flat month read as a mountain range — on the ambient morning curve and on the History page alike, in either lens, at 1W and 1M especially. Job `track-true-weight-trend`, moment `js-2-judge` (*"see a smoothed trend line that absorbs water-weight noise — so I can decide whether to adjust anything based on real movement, not noise"*), secondary `js-4-glance`. **No new job-story moment**: the job already names the outcome; this was a presentation defect against it, live on production data on the day it was reported. The fix: a minimum visible y-span of 2.0 kg, absolute, with both bounds snapped outward to a 0.5 kg grid, applied by one rule to both lenses on both surfaces at every scale. A stalled month now sits as a near-flat stroke inside a clean `76.0 … 78.5` band; a real 1M loss still drops through ~40 % of the chart; a 6M decline keeps its ordinary range with clean edges.

The KPI story is structural again, in the other direction from the last two features: **nothing is instrumented, because a render rule emits nothing** (ADR-009 purity). KPI-9 (stalled-reads-stalled, 0 false alarms over 7 dogfood mornings) is self-reported; the arithmetic is AT- and PBT-pinned, so what dogfood measures is the *taste* of two constants (OQ-12 = 2.0 kg, OQ-14 = 0.5 kg), each retunable in one line.

## Key Decisions

- **DISCUSS (D6–D9, user-locked; A25–A31)**: D6 minimum visible span **2.0 kg, absolute kg, not relative** — honesty across scales matters more than adaptivity in a single-user, metric-only product. D7 one rule, both lenses, both surfaces, every scale — it lives in the shared engine (ADR-008 parity by construction). D8 the floor widens, never clips: span ≥ 2.0 keeps the auto-range; below it `[mid − 1.0, mid + 1.0]`; degenerate windows fall under the same rule, never a zero-height axis. D9 clean bounds: both snap **outward** to 0.5 kg on every window, so no bound ever reads `77.42234`. A29 deliberately left placement (client `graph.js` vs server pure core) open with equal weight, flagging the testability difference for DESIGN.
- **DESIGN (D-27–D-32, ADR-012)**: **D-27 placement = server-side pure core function, projected onto both JSON reads, consumed by the engine.** Decided on testability, not diff size: the suite has no browser and the repository no JS runner, so a client rule would be assertable only by source-regex (US-009's palette precedent proves presence, never arithmetic), while the @property honesty scenario maps 1:1 onto a Hypothesis test over a pure function; the per-feature mutation gate only reaches Python, so a JS rule would carry both product constants outside every gate the project has; and uPlot's own default range is unsafe on exactly the degenerate case this feature repairs (span 0 ⇒ pad by |value| ⇒ a 0…154 kg axis), so any client placement would reimplement range logic anyway. Rejected: client-side `scales.y.range`; hybrid (two definitions of one rule, forbidden by A29). **D-28** the auto branch is an explicit formula (`min − 0.1·span`, `max + 0.1·span`, then snap), not a uPlot replay — identical to uPlot-then-snap for spans in [2, 10) kg, ≤ 0.5 kg apart above; A28 refined, recorded as a Changed Assumption. **D-29** 0 values ⇒ `None` / `null`; 1 or all-equal ⇒ the floored band; gap nulls never reach the function. **D-30** `FLOOR_KG`, `GRID_KG`, `AUTO_PAD_FRACTION` in `core/axis.py` only; snap `⌊2x + ε⌋/2` / `⌈2x − ε⌉/2` with ε = 1e-9 so bounds are exact half-integers on the wire. **D-31** `y_range: [lo, hi] | null`, key always present, additive; engine applies it only behind a shape guard, otherwise degrades to uPlot's own range — an imperfect axis, never a blank chart. **D-32** nothing else moves: no route, telemetry, C4, origin, port or CLAUDE.md change; `SHELL_CACHE -v4 → -v5` because the pre-cached `graph.js` changed.
- **DISTILL**: 13 scenarios / 13 executions on `milestone-11-honest-axis.feature`, error-edge share 54 %; RED gate **12 MISSING_FUNCTIONALITY / 1 GREEN-preserved / 0 BROKEN**, zero production scaffolds (the oracle `expected_range` lives test-side, implemented TO, never imported). The single GREEN-preserved scenario — "The axis frames the line and never moves it" — is the honest signature of a presentation delta beside a shipped series and was kept as the G-3 regression guard. Seeds were calibrated against the production Kalman smoother before any bound was written (a 0.25–0.3 kg/wk raw decline compresses to ~0.8 kg of trend at 1M). Placement (D-27) meant DISTILL owed no PBT — the paired property was DELIVER's, per the ADR-025 split.

## Lessons Learned

1. **Placement decided on testability turned an unfalsifiable rule into a mutation-gated one.** DISCUSS left client vs server open with equal weight; the smallest diff was a `scales.y.range` function in `graph.js`. DESIGN chose the server for three reasons that are all about *who can check it*: the suite has no browser and no JS runner, the mutation gate only reaches Python, and uPlot's default is wrong on exactly the degenerate case. The payoff was immediate and measurable — the @property honesty scenario became a 17-test Hypothesis suite, cosmic-ray executed 237 mutants on the rule and killed every non-equivalent one, and the two taste constants (the only product risk DISCUSS named) sit inside the gate. The disclosed cost — a presentation number riding on data endpoints — was two floats per response. When the question is "where does this arithmetic live", ask first which placement the project's gates can reach.
2. **What the suite cannot assert, pin by source inspection and say so.** The engine's guard and the cache bump are JavaScript; no test in this repository can execute them. Rather than pretend, 02-01 made its own RED anchor a source-inspection test (`test_axis_engine_wiring.py`, `# bypass:` documented — the US-009 palette-guard precedent) that pins presence: `y_range` referenced, guard clauses present, no standalone rule literal, `-v5` with `APP_SHELL` intact. It proves shape, never behaviour; the behaviour is owed to dogfood and the D-31 fault list, and both the roadmap and the DoD say so in those words. A textual pin that is honest about its limits is worth more than a scenario that claims coverage it cannot have.
3. **A renegotiation sweep must cover what the feature is told to change, not only what it adds.** DISTILL's "Inherited-AT Renegotiations: None" was verified by grep — for readers of the `/entries` / `/trend` body key set, the surface this feature extends. It missed that the previous feature's finalize had pinned `SHELL_CACHE == "-v4"` by exact name, while DESIGN D-32 mandated `-v5`; the pin was guaranteed to red. The roadmap reviewer caught it; 02-01 amended it with the intent written into the docstring. Two corrections carry forward: sweep every shipped assertion over every value the feature is *mandated* to change (here: the cache name, a mandate stated three times upstream), and prefer intent-shaped pins ("moved past the previous name") over exact-value pins for anything that versions.
4. **The mutation gate found one thing review could not: a contract no shipped path exercises.** Review and PBT covered the arithmetic completely; the one survivor was `frozen=True → False` on `AxisRange` — under the mutant a core value type quietly becomes mutable and unhashable, against ADR-005, and nothing in the product mutates or hashes an axis so no behavioural test could see it. Closed with one property (equal reads hash alike; assignment raises `FrozenInstanceError`) and zero production change. Same lesson as entry-date-picker from the other side: review reasons about the code that exists, mutation about the tests that don't — and sometimes what's missing is a pin on the *paradigm*, not on behaviour.
5. **A demo probe is evidence only of what it actually reached.** The "empty window" probe claimed a `today` five months before the record; the server clamped it to the skew frame — by design, A5 — and answered the current week. The demo therefore carries no empty-window read, and the DoD table says so rather than letting the probe's label stand. The empty case is pinned by two ATs. Read the raw output before recording what a demo showed.
